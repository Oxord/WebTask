# Декор для дома — интернет-магазин

Интернет-магазин товаров для декора дома: каталог с фильтрами и поиском, акции, корзина
и оформление заказа, отзывы с модерацией, личный кабинет и админ-панель с разделением
прав (администратор / модератор / покупатель).

**Стек:** чистый PHP 8.3 без фреймворков, MySQL 8, Apache 2, HTML/CSS/vanilla JS,
PHPUnit 11. Запускается локально одной командой.

---

## Как запустить

Есть два способа. **Вариант А (Docker)** — рекомендуемый: ничего не ставится в систему
и окружение одинаково на любой машине. **Вариант Б (без Docker)** — если Docker ставить
не хочется: PHP и MySQL устанавливаются локально, запуск полностью из терминала.

---

## Вариант А — через Docker

### Шаг 1. Установите Docker

Нужен **только Docker** — PHP, MySQL и Apache ставить на компьютер не надо, они
запускаются внутри контейнеров.

| Система | Что установить |
|---|---|
| **Windows 10/11** | [Docker Desktop для Windows](https://www.docker.com/products/docker-desktop/). При установке согласитесь на использование WSL 2, если предложит. |
| **macOS** | [Docker Desktop для Mac](https://www.docker.com/products/docker-desktop/) — выберите сборку под свой процессор (Apple Silicon или Intel). |
| **Linux** | [Docker Engine](https://docs.docker.com/engine/install/) + [плагин Compose](https://docs.docker.com/compose/install/linux/). Либо Docker Desktop. |

Проверьте, что всё установилось и **Docker запущен** (на Windows и macOS нужно открыть
приложение Docker Desktop и дождаться статуса *Running*):

```bash
docker --version
docker compose version
docker info
```

Если `docker info` пишет `Cannot connect to the Docker daemon` — Docker не запущен,
откройте Docker Desktop и подождите 10–30 секунд.

### Шаг 2. Получите код и поднимите контейнеры

```bash
git clone https://github.com/Oxord/WebTask.git
cd WebTask

docker compose up -d --build
```

Первая сборка занимает 2–5 минут: скачиваются образы PHP и MySQL и компилируются
расширения. Последующие запуски — секунды.

### Шаг 3. Установите зависимости PHP

```bash
docker compose exec web composer install
```

Этот шаг обязателен: каталог `vendor/` не хранится в репозитории (так принято — это
сгенерированный код, который восстанавливается из `composer.lock`).

### Шаг 4. Откройте сайт

| Что | Адрес |
|---|---|
| Витрина | **http://localhost:8081** |
| Админ-панель | **http://localhost:8081/admin** |

База данных создаётся и наполняется демо-данными автоматически при первом старте —
ничего импортировать вручную не нужно.

### Проверка, что всё работает

```bash
docker compose ps                              # все три контейнера должны быть Up
docker compose exec web vendor/bin/phpunit     # 202 теста, ожидается OK
./scripts/smoke.sh                             # проверка маршрутов, все PASS
```

На Windows `smoke.sh` запускайте из **Git Bash** или WSL (это bash-скрипт).
В PowerShell вместо него можно просто открыть сайт в браузере.

Если вы поменяли порт, укажите его скрипту:

```bash
SMOKE_BASE_URL=http://localhost:8090 ./scripts/smoke.sh
```

## Вариант Б — без Docker, из терминала

Подходит, если Docker ставить не хочется. Понадобятся PHP 8.3+, MySQL и Composer,
установленные на компьютере. Работает на Windows, macOS и Linux.

### Шаг 1. Установите PHP, MySQL и Composer

**Windows** — проще всего через [Chocolatey](https://chocolatey.org/install)
(PowerShell от имени администратора):

```powershell
choco install php mysql composer -y
```

Без Chocolatey — вручную: [PHP](https://windows.php.net/download/) (сборка Thread Safe,
каталог с `php.exe` добавить в `PATH`), [MySQL](https://dev.mysql.com/downloads/installer/),
[Composer](https://getcomposer.org/Composer-Setup.exe). После установки PHP скопируйте
`php.ini-development` в `php.ini` и раскомментируйте строки `extension=pdo_mysql`,
`extension=gd`, `extension=mbstring` — скрипт запуска подскажет, если чего-то не хватает.

**macOS:**

```bash
brew install php@8.3 mysql@8.0 composer
brew link --overwrite --force php@8.3
brew link --overwrite --force mysql@8.0
brew services start mysql@8.0
```

**Ubuntu / Debian:**

```bash
sudo apt install php8.3-cli php8.3-mysql php8.3-gd php8.3-mbstring mysql-server composer
sudo systemctl start mysql
```

### Шаг 2. Запустите

**Windows** — двойной клик по `scripts\serve-native.bat` либо в терминале:

```powershell
.\scripts\serve-native.bat
```

Можно и напрямую PowerShell-скриптом, но тогда Windows может заблокировать запуск
неподписанного файла — `.bat` эту проблему обходит:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\serve-native.ps1
```

**macOS / Linux:**

```bash
./scripts/serve-native.sh
```

Скрипт всё делает сам: проверяет версии и расширения PHP, создаёт базу и пользователя,
загружает схему и демо-данные, ставит зависимости и поднимает сервер. Ничего в систему
он не устанавливает — если чего-то не хватает, просто покажет нужную команду и остановится.

Дополнительные параметры:

| Что нужно | Windows | macOS / Linux |
|---|---|---|
| Другой порт | `.\scripts\serve-native.bat -Port 8090` | `PORT=8090 ./scripts/serve-native.sh` |
| У `root` задан пароль | `.\scripts\serve-native.bat -AdminPass "пароль"` | `MYSQL_ADMIN_PASS=пароль ./scripts/serve-native.sh` |
| Пересоздать базу | `mysql -u root -e "DROP DATABASE decor_home;"` | `mysql -u root -e 'DROP DATABASE decor_home;'` |

После удаления базы просто запустите скрипт снова — схема и демо-данные зальются заново.

Остановка — `Ctrl+C`.

### Чем этот вариант отличается

Сайт работает полностью, но по мелочам он слабее «докерного»:

- **Встроенный сервер PHP не читает `.htaccess`.** Его правила (маршрутизация через
  фронт-контроллер и запрет доступа к `.env`, `.git`, `composer.json`) воспроизведены
  в `scripts/router.php`. Заголовки безопасности при этом выставляет сам
  `public/index.php`, так что они на месте в обоих вариантах.
- **Нет gzip-сжатия и кэш-заголовков для статики** — их в варианте А даёт Apache
  (`mod_deflate`, `mod_expires`). Это влияет только на скорость загрузки, не на работу.
- **Версии PHP и MySQL — те, что стоят у вас**, а не зафиксированные 8.3 и 8.0.
  Скрипт проверяет минимальную версию PHP, но полного совпадения окружения не гарантирует.
- **Встроенный сервер PHP не предназначен для продакшена** — только для локальной работы.
  На Windows он вдобавок обрабатывает запросы по одному: параллельная выдача
  (`PHP_CLI_SERVER_WORKERS`) там не поддерживается, поэтому страницы грузятся чуть медленнее.

Интеграционные тесты в этом варианте требуют отдельной тестовой базы, поэтому их проще
запускать через Docker. Юнит-тесты работают всегда:

```bash
vendor/bin/phpunit --testsuite Unit
```

## Если порт 8081 занят (вариант А)

Симптом: `docker compose up` падает с `port is already allocated`.

Создайте файл `.env` и укажите свободный порт — больше ничего менять не нужно:

```bash
cp .env.example .env
```

```ini
WEB_PORT=8090
```

```bash
docker compose up -d
```

Сайт станет доступен на http://localhost:8090. Править `APP_URL` не нужно: по умолчанию
он пуст, и приложение формирует относительные ссылки, которые работают на любом порту.

`.env` не обязателен: если файла нет, `docker-compose.yml` подставит значения по
умолчанию из `.env.example`. Файл нужен именно для того, чтобы что-то переопределить.

Порт MySQL наружу (по умолчанию `3307`) меняется переменной `DB_PORT_HOST`. Он нужен
только чтобы подключиться к базе GUI-клиентом вроде DBeaver или TablePlus; само
приложение обращается к MySQL внутри сети Docker и от этого порта не зависит.

## Почему устроено именно так

**Почему Docker, а не «поставить PHP и MySQL на компьютер».**
ТЗ требует стек PHP + MySQL, но версии и настройки на разных машинах различаются:
где-то PHP 7.4 без `pdo_mysql`, где-то MySQL 5.7 без поддержки нужного синтаксиса,
где-то нет Apache с `mod_rewrite`. В контейнерах зафиксированы точные версии
(PHP 8.3, MySQL 8.0) со всеми нужными расширениями и модулями, поэтому проект
одинаково работает на Windows, macOS и Linux и не требует настройки окружения.
На компьютере при этом ничего не устанавливается и не изменяется — всё удаляется
одной командой `docker compose down -v`.

Это рекомендация, а не жёсткое требование: код на Docker никак не завязан, поэтому
есть вариант Б с локальными PHP и MySQL. Платой за него будут ровно те различия,
что перечислены в разделе «Чем этот вариант отличается».

**Почему база наполняется сама.**
Файлы `db/01_schema.sql` и `db/02_seed.sql` подключены в
`/docker-entrypoint-initdb.d` — официальный образ MySQL выполняет такие скрипты при
первой инициализации в алфавитном порядке. Схема, индексы и демо-данные появляются
без ручного импорта. Побочный эффект: скрипты отрабатывают **только на пустой базе**,
поэтому после правок в SQL базу нужно пересоздать (см. ниже).

**Почему три контейнера, а не два.**
`db_test` — отдельная база для интеграционных тестов, поднятая в `tmpfs` (в памяти)
и загружающая только схему, без демо-данных. Так тесты не могут испортить данные,
которые вы видите в браузере, а каждый тест выполняется в транзакции с откатом.
Наружу этот контейнер не публикуется.

**Почему нет фреймворка.**
Это требование ТЗ (п.8: HTML, CSS, JavaScript, PHP, MySQL). Поэтому реализован
минимальный собственный слой: единая точка входа `public/index.php` с таблицей
маршрутов, тонкие контроллеры, репозитории для доступа к данным и сервисы для
бизнес-логики.

**Почему `.env` не в репозитории.**
Файлы с настройками окружения не версионируются — это стандартная практика, иначе
чужие пароли и порты попадают в чужие клоны. В репозитории лежит шаблон
`.env.example`, а значения по умолчанию продублированы в `docker-compose.yml`,
чтобы проект поднимался без подготовки.

## Полезные команды (вариант А)

```bash
# Логи (например, если страница отдаёт 500)
docker compose logs -f web

# Оболочка внутри контейнера
docker compose exec web bash

# Только юнит-тесты / только интеграционные
docker compose exec web vendor/bin/phpunit --testsuite Unit
docker compose exec web vendor/bin/phpunit --testsuite Integration

# Пересобрать минифицированные CSS/JS (public/assets/dist)
docker compose exec web php scripts/build-assets.php

# Подключиться к базе в консоли
docker compose exec db mysql -udecor -pdecor_secret decor_home

# Остановить (данные сохраняются)
docker compose stop

# Остановить и удалить контейнеры (данные в томе сохраняются)
docker compose down

# Полностью сбросить, включая базу: при следующем up данные создадутся заново
docker compose down -v
```

**Пересоздать базу с нуля** (после правок в `db/*.sql` или если данные испортились):

```bash
docker compose down -v
docker compose up -d
```

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker не запущен. Откройте Docker Desktop и дождитесь статуса *Running*. |
| `port is already allocated` | Порт занят другой программой. Задайте `WEB_PORT` в `.env` (см. выше). |
| Страница отдаёт 500 | Скорее всего не выполнен `composer install`. Проверьте логи: `docker compose logs web`. |
| `Class "App\..." not found` | Не выполнен `composer install` либо нужно обновить автозагрузчик: `docker compose exec web composer dump-autoload`. |
| Сайт открывается, но без стилей | Проверьте, что открываете именно порт из `WEB_PORT`. Обновите страницу с `Ctrl+F5` — мог закешироваться старый CSS. |
| Интеграционные тесты падают на подключении | Контейнер `db_test` ещё поднимается. Подождите 20–30 секунд после `up` и повторите. |
| MySQL не стартует после правки SQL | Синтаксическая ошибка в `db/*.sql` останавливает инициализацию. Смотрите `docker compose logs db`, исправьте и выполните `docker compose down -v && docker compose up -d`. |
| На Windows не запускается `./scripts/smoke.sh` | Это bash-скрипт. Запускайте из Git Bash или WSL. |
| *(без Docker)* `MySQL не отвечает` | Сервер не запущен: `brew services start mysql@8.0` или `sudo systemctl start mysql`. Если у `root` есть пароль — `MYSQL_ADMIN_PASS=... ./scripts/serve-native.sh`. |
| *(без Docker)* `нет расширения PHP: pdo_mysql` | Установлен PHP без нужных расширений: `brew install php@8.3` или `sudo apt install php8.3-mysql php8.3-gd php8.3-mbstring`. |
| *(без Docker)* Стили и картинки не грузятся | Сервер запущен без роутера. Запускайте только через скрипт (`serve-native.sh` / `serve-native.bat`) — он передаёт `scripts/router.php`, который отдаёт статику. |
| *(Windows)* «Выполнение сценариев отключено в этой системе» | Запускайте `scripts\serve-native.bat`, а не `.ps1` напрямую — обёртка обходит политику выполнения. |
| *(Windows)* `php не является внутренней или внешней командой` | Каталог с `php.exe` не добавлен в `PATH`. Перезапустите терминал после установки. |

## Структура проекта

```
.
├── docker/
│   ├── php/              # Dockerfile образа web (php:8.3-apache) и php.ini
│   └── apache/           # vhost Apache
├── db/
│   ├── 01_schema.sql     # таблицы, индексы, внешние ключи
│   └── 02_seed.sql       # демо-данные
├── public/               # DocumentRoot
│   ├── index.php         # единая точка входа: маршруты, проверка CSRF, обработка ошибок
│   ├── .htaccess         # роутинг + заголовки безопасности
│   └── assets/           # css, js, изображения, загрузки
├── src/
│   ├── Core/             # Router, Database, View, Session, Csrf, Validator, Auth, Cache
│   ├── Repository/       # доступ к данным (только prepared statements)
│   ├── Service/          # бизнес-логика: корзина, заказы, отзывы, статистика
│   ├── Middleware/       # проверки доступа
│   └── Controller/       # публичные + Admin/
├── views/                # шаблоны: layouts, partials, pages, admin
├── tests/
│   ├── Unit/             # быстрые, на моках
│   └── Integration/      # против реальной БД db_test
├── scripts/
│   ├── smoke.sh          # проверка маршрутов и кодов доступа
│   └── build-assets.php  # минификация CSS/JS
├── docker-compose.yml
└── .env.example
```

Подробности о реализации, соответствии пунктам ТЗ и осознанных упрощениях —

## Важно про безопасность

Проект рассчитан на **локальный запуск** для демонстрации и проверки. Пароли в
`.env.example` (`decor_secret`, `root_secret`) и пароли демо-аккаунтов — заведомо
простые и предназначены только для локальной работы. Перед публикацией в интернет
их необходимо заменить, а также выставить `APP_ENV=prod` и `APP_DEBUG=false`, чтобы
подробности ошибок не показывались посетителям.
