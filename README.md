# Декор для дома — интернет-магазин

Учебный/демонстрационный интернет-магазин декора для дома: каталог товаров с категориями,
акции, корзина и оформление заказа, отзывы с модерацией, личный кабинет и админ-панель.

## Стек

- **Backend:** чистый PHP 8.3 (без фреймворков), PDO для работы с MySQL
- **Frontend:** HTML5, CSS3, vanilla JS
- **База данных:** MySQL 8.0
- **Веб-сервер:** Apache 2 (`mod_rewrite`, `mod_deflate`, `mod_expires`, `mod_headers`)
- **Инфраструктура:** Docker / Docker Compose
- **Тесты:** PHPUnit 11 (Unit + Integration)

## Быстрый старт

Требуется установленный Docker и Docker Compose.

```bash
# 1. Скопировать переменные окружения (файл .env уже создан и готов к работе из коробки)
cp .env.example .env   # если нужно пересоздать

# 2. Собрать и поднять контейнеры
docker compose up -d --build

# 3. Установить зависимости PHP
docker compose exec web composer install
```

При первом запуске MySQL контейнер `db` автоматически выполнит `db/01_schema.sql` и
`db/02_seed.sql` из каталога `/docker-entrypoint-initdb.d` — база будет создана и заполнена
демо-данными без дополнительных действий.

### Адреса

| Что | URL |
|---|---|
| Витрина | http://localhost:8081 |
| Админ-панель | http://localhost:8081/admin |
| MySQL (основная БД, порт наружу) | `localhost:3307` |

### Тестовые аккаунты

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@decor.local` | `Admin123!` |
| Модератор | `moderator@decor.local` | `Moder123!` |
| Покупатель | `user@decor.local` | `User123!` |

Дополнительно в демо-данных есть пять покупателей (`kovaleva@`, `kuznetsova@`, `nikitin@`,
`tarasova@`, `egorov@` — все `@example.com`, пароль `User123!`). Они нужны, чтобы отзывы
на сайте выглядели живыми — от разных людей, а не от одного аккаунта.

## Тесты

```bash
# Юнит- и интеграционные тесты (интеграционные используют сервис db_test)
docker compose exec web composer test

# Или напрямую через phpunit
docker compose exec web vendor/bin/phpunit
docker compose exec web vendor/bin/phpunit --testsuite Unit
docker compose exec web vendor/bin/phpunit --testsuite Integration
```

Сервис `db_test` (MySQL 8, данные в tmpfs) поднимается вместе с остальными контейнерами и
инициализируется только схемой (`01_schema.sql`, без seed-данных) — так тесты стартуют с
чистой базой каждый раз при пересоздании контейнера.

## Smoke-тест

После запуска приложения можно быстро проверить, что ключевые маршруты отвечают ожидаемыми
кодами:

```bash
./scripts/smoke.sh
```

Скрипт проверяет `/`, `/about`, `/catalog`, `/reviews`, `/contacts`, `/promotions`, `/cart`,
`/login`, `/register` (ожидается 200), `/admin` без авторизации (ожидается 302) и
`/nonexistent` (ожидается 404). Выводит `PASS`/`FAIL` по каждому маршруту и завершается кодом
`1`, если что-то не прошло.

## Структура каталогов

```
.
├── docker/
│   ├── php/            # Dockerfile образа web (php:8.3-apache) и php.ini
│   └── apache/          # vhost-конфигурация Apache
├── db/
│   ├── 01_schema.sql     # DDL: таблицы, индексы, внешние ключи
│   └── 02_seed.sql       # демо-данные (пользователи, товары, акции, заказы, отзывы)
├── public/               # DocumentRoot: index.php, .htaccess, assets/
│   └── assets/
│       ├── img/          # SVG-плейсхолдеры товаров, акций, логотип, слайды hero
│       └── uploads/       # загружаемые файлы (не версионируется, кроме .gitkeep)
├── src/                  # PHP-код приложения (PSR-4 App\)
├── views/                # шаблоны страниц
├── tests/
│   ├── Unit/
│   └── Integration/
├── scripts/
│   └── smoke.sh          # smoke-тест ключевых маршрутов
├── docker-compose.yml
├── composer.json
├── phpunit.xml
└── .env / .env.example
```

*(`src/`, `views/`, `tests/` наполняются в рамках отдельных задач — здесь описана структура
проекта в целом.)*

## Соответствие ТЗ (инфраструктурная часть)

- Стек HTML/CSS/JS/PHP/MySQL без фреймворков — соблюдено, `web` собран на `php:8.3-apache`
  без каких-либо MVC-фреймворков.
- Локальный запуск через Docker Compose одной командой — `docker compose up -d --build`.
- Отдельная тестовая база данных (`db_test`) с чистой схемой для интеграционных тестов,
  изолированная от основной БД (`db`) и не публикуемая наружу.
- Схема БД покрывает все сущности магазина: пользователи с ролями (`admin`/`moderator`/`user`),
  категории, товары, акции со связкой многие-ко-многим с товарами, заказы с позициями,
  отзывы с модерацией (`pending`/`approved`/`rejected`) и обратная связь (`contact_messages`).
- Индексы под типовые выборки каталога (по категории/активности, по избранным товарам,
  полнотекстовый поиск по названию и описанию) и админки (заказы по пользователю/дате/статусу,
  отзывы по статусу).
- Демо-данные наполнены реалистичным русскоязычным контентом: 24 товара, 5 категорий,
  4 акции (в том числе одна завершившаяся), 12 отзывов в разных статусах, 2 заказа
  (включая завершённый — для проверки правила «отзыв доступен только после покупки»).
- Пароли демо-пользователей захешированы bcrypt (`$2y$`, cost 10) и проверены через
  `password_verify()` в PHP 8.3.
- Заголовки безопасности (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`),
  запрет доступа к `.env`/`composer.json`/`.git` и роутинг через фронт-контроллер настроены
  в `public/.htaccess`.
- `php.ini` донастроен под безопасные сессии (`httponly`, `SameSite=Lax`, strict mode),
  разумные лимиты загрузки файлов и включённый OPcache.
